# Software Testing and Quality Assurance Portfolio

### How can I ensure that my code, program, or software is functional and secure?

I can build confidence in my software by testing it against the requirements instead of assuming it works because it runs. Unit tests should cover valid inputs, invalid inputs, and boundary conditions. For a contact service, this includes checking required fields, length limits, and how the program handles duplicate IDs or missing contacts. Running these tests after changes helps catch problems before they affect other parts of the program. Security also requires input validation, careful error handling, and reviewing code and dependencies for vulnerabilities. Passing unit tests is useful, but it does not guarantee that software is completely secure.

### How do I interpret user needs and incorporate them into a program?

I start by breaking user needs into specific requirements that I can implement and test. For example, a request to manage contacts can be divided into adding, updating, and deleting contact information. Each operation needs clear rules about the data it accepts and what should happen when an action cannot be completed. If a requirement is unclear, I would ask questions rather than make assumptions. Connecting each requirement to a test helps me check that the program does what the user needs.

### How do I approach designing software?

I approach software design by understanding the requirements first and then dividing the program into smaller parts with clear responsibilities. For a contact service, separating the contact data from the logic that manages contacts makes the program easier to understand and maintain. I also consider invalid inputs and possible failures during the design process. Building and testing smaller pieces gives me a chance to catch mistakes early. As the program develops, I can use test results and feedback to improve the design while keeping it focused on the original requirements.
